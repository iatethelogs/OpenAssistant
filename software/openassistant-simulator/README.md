# OpenAssistant Simulator

Windows-приложение для тестирования голосового ассистента без физической колонки. Эмулятор использует микрофон и динамики компьютера и подключается к OpenAssistant Server по WebSocket.

## Возможности

- Прослушивание кодового слова локальным детектором WakeForge/TFLite.
- Буферизация одной секунды звука перед активацией, чтобы начало команды не потерялось.
- Автоматическое определение окончания речи по паузе, а также ручное завершение записи.
- Передача PCM16 16 кГц на сервер и отображение распознанного GigaAM текста.
- Отображение текста ответа языковой модели и текущего состояния ассистента.
- Воспроизведение голосового ответа, поступающего от сервера бинарными PCM-фреймами.
- Приём медиакоманды `play_media` и прямое воспроизведение интернет-радио и доступных MP3/AAC-треков на компьютере.
- Отображение фактической частоты дискретизации и числа каналов декодированного музыкального потока.

## Запуск

Установите .NET SDK 10 на Windows и выполните:

```powershell
cd software/openassistant-simulator
dotnet run
```

Введите `ws://<адрес-сервера>:5055/ws` и ключ устройства, заданный в настройках Linux-сервера. Для подключения из сети сервер должен прослушивать LAN-адрес; в недоверенной сети используйте `wss://`. Можно произнести команду после слова активации, нажать «Говорить» для ручной записи либо написать текстовый запрос.

## Детектор слова активации

Эмулятор принимает путь к локальному исполняемому файлу TFLite-детектора и его параметры. Детектор получает поток PCM16 mono 16 кГц через stdin и выводит JSON-событие при срабатывании, например `{"type":"wake","word":"мартин","score":0.94}`.

Понадобится отдельный исполняемый детектор, совместимый с моделью WakeForge и её аудиофронтендом. Сам эмулятор не интерпретирует .tflite напрямую.

## Протокол звука

После обнаружения кодового слова эмулятор сначала отправляет событие `wake` с текстом слова активации, затем предварительно записанный фрагмент и последующий звук на сервер бинарными WebSocket-сообщениями. После обнаружения паузы в речи отправляется `{"type":"end"}`.

GigaAM обрабатывает аудио на сервере. Клиент получает событие `transcript` и поток текста `text`, а также фреймы PCM после `audio_start`. Команды `play_media` и `stop_media` управляют плеером на стороне клиента: музыкальные потоки не проходят через сервер.

Для микрофона используется 16 кГц, моно, PCM16. Для голосового ответа используется частота, указанная Qwen3-TTS. Для музыки Windows Media Foundation открывает ссылку на исходный поток и декодирует её независимо от микрофона: например, поток 44,1 кГц стерео не преобразуется сервером в 16 кГц. Фактические параметры отображаются рядом с плеером. Формат и качество зависят от источника и доступных декодеров Windows.

Встроенный VAD использует уровень сигнала и оценку фонового шума. Отдельный процесс детектора WakeForge должен поддерживать PCM16-ввод и JSONL-события; для запуска `.tflite` требуется совместимый аудиофронтенд. Для шумных помещений потребуется более точное определение речи.
