# OpenAssistant Server

OpenAssistant Server — локальный сервер голосового ассистента для Linux на C# и .NET 10. Принимает речь с подключённых устройств, обращается к языковой модели, синтезирует голосовой ответ и передаёт звук обратно по WebSocket.

## Возможности

- Локальные языковые модели с OpenAI-совместимым API.
- Русскоязычное распознавание речи GigaAM.
- Синтез речи Qwen3-TTS с выбором голоса.
- Загрузка моделей из Hugging Face в веб-интерфейсе с прогрессом, отменой и продолжением частичных файлов.
- Отдельные профили запуска LLM, STT и TTS: GPU UUID, параметры, окружение, путь к модели и контроль процесса.
- Мониторинг температуры GPU, VRAM, загрузки и мощности, журналов процесса и готовности API.
- Передача текста ответа по мере генерации, озвучивание по фразам и прерывание ответа.
- Единая панель управления с мастером первого запуска, каталогом моделей, настройкой голоса, подключением колонок, мониторингом и реальными тестами задержки LLM/STT/TTS.
- Агентный цикл OpenAI-compatible tool_calls: поиск и воспроизведение Яндекс Музыки, радио, чтение состояний Home Assistant и разрешённые команды умному дому.
- Веб-интерфейс диалога, панель управления моделями и журнал серверного распознавания речи и ответов LLM.
- Управление устройствами Home Assistant через локальный API.
- Поиск интернет-радиостанций в каталоге Radio Browser и прослушивание в браузере.
- Подключение Яндекс Музыки через Яндекс ID или OAuth-токен, поиск композиций и прямое воспроизведение доступных MP3/AAC-треков.
- Управление подключениями внешних сервисов из одной страницы: авторизация, проверка состояния и отключение.

## Требования

Linux, .NET SDK 10 и NVIDIA Driver с утилитой `nvidia-smi` для просмотра доступных видеокарт. Для работы нейросетей потребуются установленные движки с поддержкой GPU и соответствующие модели.

Распознавание речи подключается по HTTP через `POST /v1/audio/transcriptions`. Синтез Qwen3-TTS подключается через `POST /synthesize` с ответом WAV PCM16 mono. GigaAM и Qwen3-TTS выполняются внешними GPU-движками; OpenAssistant управляет их процессами и отправляет запросы, но не содержит их нейросетевых runtime.

## Запуск

```bash
cd software/openassistant-server
dotnet run
```

После запуска в терминале появится логотип OpenAssistant и адреса веб-интерфейсов.

- **Единая панель управления:** `http://127.0.0.1:5055/`
- **Диалог:** `http://127.0.0.1:5055/chat.html`
- **Настройки:** `http://127.0.0.1:5055/settings.html`
- **Подключения:** `http://127.0.0.1:5055/connections.html`
- **Модели и GPU:** `http://127.0.0.1:5055/models.html`
- **Музыка:** `http://127.0.0.1:5055/media.html`
- **Журнал диалогов:** `http://127.0.0.1:5055/events.html`

## Модели и GPU

На странице «Модели и GPU» доступны три независимых профиля: LLM, GigaAM и Qwen3-TTS. Для каждого указываются исполняемый файл Linux, рабочая папка, путь к весам, аргументы запуска по одному на строку, переменные окружения, адрес API проверки готовности и выбранные видеокарты. Привязка к GPU по UUID применяется через `CUDA_VISIBLE_DEVICES`, поэтому модели можно разместить на разных картах. В аргументах используются подстановки `{model}` и `{modelDir}`.

Для скачивания укажите репозиторий Hugging Face в формате `owner/model`, выберите ревизию и файлы. Для GGUF обычно достаточно одного файла, для моделей GigaAM и Qwen3-TTS нужен комплект конфигурации и весов. Скачивание выполняется непосредственно Linux-сервером в `models/owner/model/commit`; отображаются объём, текущий файл, прогресс и ошибка. Частично полученные файлы сохраняются как `.partial` для повторного запуска загрузки. Если репозиторий требует разрешения, можно сохранить HF access token в локальных настройках.

Мониторинг показывает PID, код завершения, последние строки stdout/stderr, доступность HTTP API и показатели NVIDIA GPU: температуру, загрузку, память и энергопотребление. Статус «процесс запущен» не означает, что нейросеть готова; HTTP-проверка отображается отдельно. Не все сторонние STT/TTS API поддерживают `/health`, поэтому ответ HTTP 404 трактуется как «неизвестно», а не как подтверждение готовности.

Для LLM отдельно настраиваются температура генерации, top-p, top-k, штраф повторений и максимальное число токенов. Это параметры запроса, а не физическая температура GPU.

Движки GigaAM и Qwen3-TTS устанавливаются отдельно: скачивание весов не устанавливает Python-библиотеки и не создаёт runtime автоматически.

## Музыка

Для поиска радио используется открытый каталог Radio Browser. Найденные аудиопотоки можно воспроизвести непосредственно в браузере, если поддерживается формат станции. При команде «включи радио ...» сервер также может отправить подключённому клиенту ссылку командой `play_media`, чтобы воспроизведение выполняло само устройство.

Яндекс Музыка подключается на странице «Подключения». Нажмите «Подключить через Яндекс ID», откройте страницу подтверждения Яндекса и введите выданный код. OpenAssistant дождётся подтверждения и сохранит токен локально. Можно также вставить уже полученный OAuth-токен. После подключения можно искать треки и воспроизводить доступные MP3/AAC-файлы. OpenAssistant использует маршруты `/search` и современный подписанный `/get-file-info` (raw MP3/AAC), а при отсутствии доступного результата обращается к совместимому `/tracks/{trackId}/download-info`. Интерфейсы соответствуют библиотеке MarshalX/yandex-music-api. Ссылка на аудиофайл действует недолго и запрашивается непосредственно перед воспроизведением.

По голосовой команде «включи песню ...» сервер отправляет колонке медиакоманду с URL. Колонка самостоятельно подключается к источнику и воспроизводит поток в формате, поддерживаемом своим декодером. Сервер не проксирует и не преобразует музыку в PCM16 16 кГц. Зашифрованные потоки, недоступные варианты качества, плейлисты и музыкальная очередь пока не поддерживаются.

## Интеграции

На странице «Подключения» отображается актуальный статус Яндекс Музыки и Home Assistant. Токены не отображаются в ответах веб-интерфейса, а их действительность проверяется запросами к соответствующим сервисам.

Для Home Assistant укажите адрес локального сервера и долгоживущий токен из профиля. OpenAssistant проверит доступ к API перед сохранением. Для отключения достаточно нажать соответствующую кнопку. Radio Browser работает без учётной записи.

Для входа в Яндекс Музыку используется OAuth Device Flow с параметрами Android-клиента из открытой библиотеки MarshalX/yandex-music-api. Неофициальное взаимодействие может перестать работать при изменениях Яндекса.

## Подключение голосовых устройств

WebSocket-адрес: `/ws`. Сервер по умолчанию слушает порт 5055 на сетевых интерфейсах Linux. Локальные подключения с этого же компьютера доступны без ключа. Для Windows-эмулятора и других устройств в сети задайте ключ устройства на странице «Настройки» и укажите его в клиенте. Удалённый клиент передаёт ключ в заголовке `X-OpenAssistant-Token`. Если клиент подключается с другой машины, настройте прослушивание LAN-адреса через Kestrel и используйте защищённое `wss://` в недоверенных сетях. Входной звук: PCM16 LE mono, 16 кГц. Сообщение `{"type":"wake","word":"мартин"}` отмечает начало голосовой команды и позволяет убрать слово активации из расшифровки. Сообщение `{"type":"end"}` завершает аудиозапрос после окончания фразы; `{"type":"text","text":"привет"}` отправляет текст; `{"type":"cancel"}` прерывает ответ. Выходной голосовой звук: PCM16 LE mono с частотой, заданной в настройках синтеза. Музыкальные ссылки `play_media` передаются отдельно: аудиопоток загружает и декодирует само устройство.

## Безопасность и хранение данных

Конфигурация сохраняется в локальных JSON-файлах и не требует базы данных. Файлы с токенами и локальными настройками исключены из Git. Административные API принимают запросы только с локального адреса сервера. Для удалённого администрирования используйте защищённый локальный доступ; они не предназначены для публикации в интернет без дополнительной аутентификации и обратного прокси.

Для тестирования колонки на Windows предусмотрен отдельный [OpenAssistant Simulator](../openassistant-simulator/README.md). Кодовое слово распознаётся локально на клиенте, а полноценная расшифровка речи выполняется сервером.

## Первоначальная настройка

Откройте адрес `http://127.0.0.1:5055/` в браузере сервера либо через SSH-туннель, например `ssh -L 5055:127.0.0.1:5055 user@SERVER_IP`. В боковом меню находятся «Обзор», «Первый запуск», «Каталог и модели», «Ассистент и голос», «Инструменты и аккаунты», «Колонка и устройства», «Диагностика и тесты», «Диалог» и «Музыка и радио». Старые дополнительные страницы оставлены для расширенных параметров.

Мастер проводит через загрузку весов, настройку llama.cpp, адреса STT/TTS, включение инструментов, создание ключа колонки и проверку компонентов. В каталоге есть несколько LLM, GigaAM и Qwen3-TTS, но можно указать любой корректный репозиторий Hugging Face. Для GGUF выбирается нужная квантизация, для STT и TTS нужен полный комплект файлов. Скачивание весов само по себе не устанавливает движки инференса.

Быстрый запуск llama.cpp ищет существующий `llama-server` в стандартных каталогах Linux; пользователь выбирает GGUF, конкретные GPU, контекст, число потоков CPU и порт. Сервер создаёт профиль запуска, запускает или перезапускает процесс с `--jinja` для инструментов и подключает его HTTP API. Если llama.cpp не установлен или путь нестандартный, необходимо указать существующий исполняемый файл.

Панель показывает подключённые WebSocket-клиенты, температуру и память видеокарт, журнал процессов и статус API. Генерация нового ключа колонки делает прежний ключ недействительным для новых соединений.

В разделе тестирования доступны:
- LLM: время первого фрагмента, полное время и **приблизительная** оценка токенов в секунду по символам.
- STT: запись микрофона браузера, прослушивание WAV, распознавание, длительность и real-time factor.
- TTS: настройка текста и голоса, получение и скачивание тестового WAV, время синтеза и real-time factor.
- Совместный тест: LLM → TTS → воспроизведение звука.

Тесты выполняются через уже работающие HTTP API. Они **не загружают автоматически** произвольный чекпойнт в STT/TTS движок: тестируется модель, обслуживаемая соответствующим API. Микрофон браузера требует HTTPS или localhost; через SSH-туннель `127.0.0.1` разрешён.

## Инструменты LLM

Сервер передаёт разрешённые навыки через OpenAI-compatible `tools`/`tool_choice`, собирает потоковые `tool_calls`, проверяет аргументы, исполняет функцию и возвращает результат модели. Доступны `radio_search`, `radio_play`, `music_search`, `music_play`, `ha_get_state` и `ha_call_service`. Последний отключён по умолчанию; разрешены только явно перечисленные бытовые домены и действия. Есть ограничения на число вызовов и таймауты.

Для агентного вызова инструментов нужна LLM с корректной поддержкой function calling и соответствующий шаблон чата в llama.cpp. На моделях без этой поддержки обычные диалоги могут работать, но вызовы инструментов будут ошибаться. Имеются ограничения: нет подтверждения опасных действий с телефона, памяти между перезапусками и полноценной музыкальной очереди.
