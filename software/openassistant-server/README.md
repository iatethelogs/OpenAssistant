# OpenAssistant Server

OpenAssistant — локальная программная платформа голосового ассистента на Linux и .NET 10. Сервер обслуживает языковую модель, распознавание и синтез речи, интеграции и подключённые голосовые устройства. **«Мартин» — возможное имя отдельной колонки, а не название проекта или обязательный компонент установки.**

## Запуск

Нужен .NET 10 SDK.

```bash
cd software/openassistant-server
dotnet build -c Release -m:24
dotnet run -c Release --no-build
```

В терминале отображаются ASCII-логотип OpenAssistant и один адрес интерфейса. Серверные логи доступны на `/logs.html`.

Для открытия панели с Windows через SSH используйте туннель:

```powershell
ssh -N -L 5055:127.0.0.1:5055 root@SERVER_IP
```

Затем откройте `http://127.0.0.1:5055/`.

## Интерфейс

- **`/`** — основной тёмный дашборд: состояние LLM, STT, TTS, GPU, памяти, диска и подключённых устройств.
- **`/setup.html`** — отдельный мастер первоначальной настройки.
- **`/#settings`** — основные настройки: поведение LLM, системный промпт, температура и голос.
- **`/#tests`** — быстрые проверки ответов LLM и синтеза речи.
- **`/#devices`** — подключение устройств и активные WebSocket-сессии.
- **`/#integrations`** — разрешения агентных инструментов.
- **`/control.html`** — расширенные параметры GPU, моделей, API и диагностики.
- **`/chat.html`** — веб-диалог.
- **`/connections.html`** — подключение Яндекс Музыки и Home Assistant.
- **`/media.html`** — музыка и интернет-радио.
- **`/logs.html`** — журнал сервера.

Административные API доступны только локально. Для работы с микрофоном браузеру требуется HTTPS либо localhost.

## Мастер установки

Мастер подготавливает **саму платформу OpenAssistant**, не создавая колонку.

**1. Языковая модель.** Выбор из подготовленного списка GGUF для видеокарт класса 8 ГБ, выбор GPU (по умолчанию автоматически), контекста и температуры с рекомендуемыми значениями. Сервер загружает веса, находит или собирает llama.cpp, запускает модель и проверяет ответ с измерением времени первого токена и скорости. При тестовом запросе можно видеть использование GPU.

**2. Распознавание.** Установка GigaAM v3, запуск HTTP-адаптера, запись 5 секунд с микрофона браузера, прослушивание оригинала, распознавание и измерение задержки и real-time factor.

**3. Синтез.** Выбор между Qwen3-TTS 0.6B CustomVoice с готовыми голосами и Qwen3-TTS 1.7B VoiceDesign, которая генерирует голос по естественно-языковому описанию. После установки можно менять голос или его описание, создавать новый WAV и слушать его прямо в мастере. VoiceDesign значительно требовательнее к памяти: на 8 ГБ VRAM она может не запуститься; предусмотрена попытка использования CPU. Описание не гарантирует абсолютно постоянный тембр между независимыми генерациями. Для фиксации тембра понадобится сохранение эталонного голоса и клонирование.

Настройки выбранного голоса сохраняются сервером в `voice-profile.local.json`. Скачивание весов и запуск проходят в серверных заданиях; прогресс и сообщения видны в веб-интерфейсе.

Автоматическая установка системных зависимостей из APT требует соответствующих прав. Сборке CUDA-версии llama.cpp нужен установленный CUDA Toolkit; совместимость PyTorch со старыми видеокартами может быть ограничена. Используются системный Python, без venv и Docker. После перезапуска сервера ранее настроенные процессы LLM/STT/TTS автоматически запускаются.

## Подключение устройств

Колонки добавляются **отдельно от мастера** через «Подключение устройства» на дашборде. Сейчас этот раздел выдаёт адрес WebSocket и общий ключ сервера и показывает активные соединения. Полноценный реестр независимых устройств, их персональные имена, настройки и права доступа ещё не реализован. В будущем там можно будет зарегистрировать конкретный экземпляр колонки с именем «Мартин» или любым другим.

## Сетевое взаимодействие

Микрофон клиента передаёт на сервер PCM16 mono 16 кГц через WebSocket. Сервер формирует WAV, распознаёт речь, отправляет текст LLM, вызывает доступные инструменты через OpenAI-совместимое function calling и синтезирует ответ. Обратный звук — PCM16 mono. Музыкальные потоки устройство получает напрямую по предоставленному сервером URL.

В наборе инструментов предусмотрены Яндекс Музыка, интернет-радио и Home Assistant. Вызовы, меняющие состояние домашней автоматизации, отключены по умолчанию.

Программная сборка и интеграционное тестирование новых мастера и адаптеров на реальном Linux-сервере всё ещё требуются.
