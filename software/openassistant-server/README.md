# OpenAssistant Server

OpenAssistant Server — локальный сервер голосового ассистента для Linux на C# и .NET 10. Принимает речь с подключённых устройств, обращается к языковой модели, синтезирует голосовой ответ и передаёт звук обратно по WebSocket.

## Возможности

- Локальные языковые модели с OpenAI-совместимым API.
- Русскоязычное распознавание речи GigaAM.
- Синтез речи Qwen3-TTS с выбором голоса.
- Настраиваемые профили запуска LLM, STT и TTS, включая выбор одной или нескольких NVIDIA GPU.
- Передача текста ответа по мере генерации, озвучивание по фразам и прерывание ответа.
- Веб-интерфейс диалога, панель управления моделями и журнал серверного распознавания речи и ответов LLM.
- Управление устройствами Home Assistant через локальный API.
- Поиск интернет-радиостанций в каталоге Radio Browser и прослушивание в браузере.
- Подключение аккаунта Яндекс Музыки по OAuth-токену, поиск композиций и прямое воспроизведение доступных MP3/AAC-треков.

## Требования

Linux, .NET SDK 10 и NVIDIA Driver с утилитой `nvidia-smi` для просмотра доступных видеокарт. Для работы нейросетей потребуются установленные движки с поддержкой GPU и соответствующие модели.

Распознавание речи подключается по HTTP через `POST /v1/audio/transcriptions`. Синтез Qwen3-TTS подключается через `POST /synthesize` с ответом WAV PCM16 mono. GigaAM и Qwen3-TTS выполняются внешними GPU-движками; OpenAssistant управляет их процессами и отправляет запросы, но не содержит их нейросетевых runtime.

## Запуск

```bash
cd software/openassistant-server
dotnet run
```

После запуска в терминале появится логотип OpenAssistant и адреса веб-интерфейсов.

- **Диалог:** `http://127.0.0.1:5055/`
- **Настройки:** `http://127.0.0.1:5055/settings.html`
- **Модели и музыка:** `http://127.0.0.1:5055/media.html`
- **Журнал диалогов:** `http://127.0.0.1:5055/events.html`

## Выбор моделей и GPU

На странице «Модели и музыка» отображается список NVIDIA GPU, определённых через `nvidia-smi`. Для каждого движка настраивается отдельный профиль: абсолютный путь к исполняемому файлу Linux, рабочая папка, аргументы запуска и номера GPU. Затем модель можно запустить и остановить из браузера.

Для ограничения GPU применяется переменная `CUDA_VISIBLE_DEVICES`. Индексы видеокарт внутри процесса могут отличаться от системных. После запуска необходимо указать адрес работающего сервиса на странице «Настройки».

Сервер управляет только процессами, запущенными через собственную панель. Внешние процессы он не завершает.

## Музыка

Для поиска радио используется открытый каталог Radio Browser. Найденные аудиопотоки можно воспроизвести непосредственно в браузере, если поддерживается формат станции. При команде «включи радио ...» сервер также может отправить подключённому клиенту ссылку командой `play_media`, чтобы воспроизведение выполняло само устройство.

Для подключения Яндекс Музыки введите OAuth-токен собственного аккаунта. После подключения можно искать треки и воспроизводить доступные MP3/AAC-файлы. OpenAssistant использует маршруты `/search` и современный подписанный `/get-file-info` (raw MP3/AAC), а при отсутствии доступного результата обращается к совместимому `/tracks/{trackId}/download-info`. Интерфейсы соответствуют библиотеке MarshalX/yandex-music-api. Ссылка на аудиофайл действует недолго и запрашивается непосредственно перед воспроизведением.

По голосовой команде «включи песню ...» сервер отправляет колонке медиакоманду с URL. Колонка самостоятельно подключается к источнику и воспроизводит поток в формате, поддерживаемом своим декодером. Сервер не проксирует и не преобразует музыку в PCM16 16 кГц. Зашифрованные потоки, недоступные варианты качества, плейлисты и музыкальная очередь пока не поддерживаются.

## Подключение голосовых устройств

WebSocket-адрес: `/ws`. Сервер по умолчанию слушает порт 5055 на сетевых интерфейсах Linux. Локальные подключения с этого же компьютера доступны без ключа. Для Windows-эмулятора и других устройств в сети задайте ключ устройства на странице «Настройки» и укажите его в клиенте. Удалённый клиент передаёт ключ в заголовке `X-OpenAssistant-Token`. Если клиент подключается с другой машины, настройте прослушивание LAN-адреса через Kestrel и используйте защищённое `wss://` в недоверенных сетях. Входной звук: PCM16 LE mono, 16 кГц. Сообщение `{"type":"wake","word":"мартин"}` отмечает начало голосовой команды и позволяет убрать слово активации из расшифровки. Сообщение `{"type":"end"}` завершает аудиозапрос после окончания фразы; `{"type":"text","text":"привет"}` отправляет текст; `{"type":"cancel"}` прерывает ответ. Выходной голосовой звук: PCM16 LE mono с частотой, заданной в настройках синтеза. Музыкальные ссылки `play_media` передаются отдельно: аудиопоток загружает и декодирует само устройство.

## Безопасность и хранение данных

Конфигурация сохраняется в локальных JSON-файлах и не требует базы данных. Файлы с токенами и локальными настройками исключены из Git. Панели управления и API настроек доступны только с локального адреса; они не предназначены для публикации в интернет без дополнительной аутентификации и обратного прокси.

Для тестирования колонки на Windows предусмотрен отдельный [OpenAssistant Simulator](../openassistant-simulator/README.md). Кодовое слово распознаётся локально на клиенте, а полноценная расшифровка речи выполняется сервером.
