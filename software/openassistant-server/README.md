# OpenAssistant Server

Сервер OpenAssistant запускает языковую модель, распознавание и синтез речи, обрабатывает запросы от колонок и других клиентов, хранит историю разговоров и подключается к внешним сервисам. Управление выполняется через браузер.

## Установка и первый запуск

Нужен Linux с **.NET 10 SDK**. Для речевых моделей используется системный Python; совместимость ускорения на GPU зависит от драйвера, CUDA и выбранной модели. Для первоначальной загрузки компонентов понадобится интернет.

Из корня репозитория:

~~~bash
cd software/openassistant-server
dotnet run -c Release
~~~

Сервер уже настроен на HTTP-порт **5055** и слушает **0.0.0.0**, поэтому панель и устройство используют один LAN-адрес, например:

- Панель: `http://192.168.1.50:5055/`
- Мастер: `http://192.168.1.50:5055/setup.html`
- Колонка/симулятор: `ws://192.168.1.50:5055/ws`

SSH-туннель для открытия панели в локальной сети не нужен.

**Панель не требует пароля.** Адреса `http://IP_СЕРВЕРА:5055/` и `/setup.html` открываются напрямую из доверенной локальной сети. По умолчанию приложение принимает запросы из RFC1918 подсетей (10/8, 172.16/12, 192.168/16) и localhost. **Не пробрасывайте порт 5055 в интернет**: административные функции и токены доступны всем в этой локальной сети.

Ключ устройства хранится в `~/.local/state/openassistant/credentials.json` (либо каталоге `XDG_STATE_HOME`), вне репозитория. При первом запуске существующий ключ из `settings.local.json` переносится без изменения. После перезапуска он снова отображается в разделе «Устройства»; новый ключ создаётся только при явном перевыпуске.

Устройства и панель подключаются к одному адресу сервера без пароля и ключа **внутри доверенной LAN**. Старый клиент с заполненным ключом также продолжит работать. Все запросы к серверу ограничены localhost и RFC1918-подсетями (10/8, 172.16/12, 192.168/16); порт **5055 нельзя открывать в интернет**. `/health` доступен в LAN для проверки связи. Сохранённый ранее ключ не удаляется, но для подключения внутри LAN он больше не нужен.

**Важно:** Basic Auth и WebSocket через `http://`/`ws://` не шифруются. Используйте только доверенную LAN, не пробрасывайте порт 5055 в интернет. Для доступа через недоверенные сети настройте TLS/HTTPS (`https://`, `wss://`) и соответствующий защищённый прокси.

Мастер последовательно предложит выбрать языковую модель, настроить распознавание и синтез речи, проверить голос и при необходимости подключить Яндекс Музыку. Модели запускаются через мастер или раздел «Модели»; автоматический старт всех движков после перезапуска сервера пока не предусмотрен.

## Настройка ассистента

В разделе «Настройки» задаются системная инструкция, параметры генерации LLM, язык и голос. Кнопка **«Профиль ассистента»** подставляет рекомендуемые начальные параметры; их можно изменить и сохранить.

Языковые модели работают через llama.cpp и OpenAI-совместимый API. Можно выбрать GGUF из каталога или указать собственную модель. Профили запуска LLM, STT и TTS настраиваются независимо.

Для русского распознавания в мастере используется **GigaAM**. Для озвучивания доступны **Qwen3-TTS** (CustomVoice, VoiceDesign, Faster Qwen) и **Piper** (русские голоса Денис, Дмитрий, Ирина и Руслан, ONNX на CPU без расхода VRAM). В разделе «Настройки → Синтез речи» можно установить и переключить движок. Piper загружает веса при первом запуске и кеширует их в `models/piper/`. Параметры Qwen (seed, sampling, манера речи) не применяются к Piper.

При выборе Piper интерфейс показывает только его параметры синтеза: **длительность фонем** (меньше 1 — речь быстрее), **Noise scale** (вариативность звука), **Noise W** (вариативность длительности фонем), **громкость** и **нормализацию амплитуды**. Параметры Qwen скрываются. Настройки применяются при следующем TTS-запросе без перезагрузки ONNX-модели.

Там же доступны режимы озвучивания: **Быстро** — синтез законченных фраз одновременно с генерацией LLM, и **Качественно** — генерация аудио после получения полного текстового ответа. Если ответ превышает лимит входного текста TTS, он делится на минимальное количество частей. Длинная речь воспроизводится через расширенный буфер клиента без отбрасывания звука при передаче быстрее реального времени.

Слово активации «Мартин» принимается даже во время голосового ответа. Повторное срабатывание останавливает генерацию, прерывает воспроизведение и запускает запись новой команды. Качество детекции при звучании своего динамика зависит от эхоподавления микрофона.

Раздел «Диагностика» позволяет записать тестовую фразу с микрофона, проверить распознавание и прослушать синтезированный ответ.

## История и профили собеседников

Разговоры сохраняются на сервере и доступны после нового подключения. В разделе «Диалог» можно выбрать имя профиля, проверить количество сохранённых обменов и удалить историю.

При ответе используются недавние реплики и фрагменты прежних разговоров, найденные по содержанию запроса. Это не автоматическое распознавание личности и не гарантия безошибочного восстановления любого старого факта. Если несколько человек используют общий профиль, их история будет общей.

Клиент может выбрать профиль отдельным WebSocket-сообщением:

~~~json
{"type":"profile","name":"Гость"}
~~~

Если профиль не выбран, используется **«Общий»**.

## Home Assistant

В разделе **«Интеграции»** укажите адрес Home Assistant и долгоживущий токен. После подключения можно обновить список устройств и увидеть их текущие состояния.

Ассистент получает данные из Home Assistant, а не из сохранённого описания дома. Выбор функции Home Assistant или Яндекс Музыки выполняет **LLM**, а не серверный парсер слов «включи» и «выключи». Для устройств модель вызывает доступные функции чтения состояния или управления; обработчики запрашивают фактические данные напрямую. Если состояние не удалось подтвердить, модель не должна выдумывать результат.

Управление устройствами **по умолчанию отключено**. Чтобы разрешить действия, включите соответствующий инструмент в разделе интеграций. Сейчас предусмотрены команды для освещения, выключателей, вентиляторов, штор и медиаплееров. Перед отправкой команды проверяется устройство, а после выполняется повторное чтение состояния. Если ожидаемый результат не подтверждён, ассистент сообщает об этом, не объявляя действие завершённым.

Поддерживаются не все домены Home Assistant и не все формулировки запросов. Изменение климатических настроек, создание автоматизаций, работа со сценами и произвольные вызовы сервисов пока не реализованы. Для критичных устройств не следует использовать управление без отдельного контроля.

## Контекст LLM и короткий диалог

В мастере модели по умолчанию задаётся **64K (65536 токенов)** через
`llama-server --ctx-size 65536`. Старые сохранённые профили с типовым
контекстом 4096 автоматически переводятся на 65536 **при следующем запуске
LLM**. Если память GPU не позволяет выделить KV-кеш на 64K, вручную уменьшите
`--ctx-size` в настройках профиля (например до 32768) и повторно запустите
модель. Максимально полезная длина зависит также от обучения конкретной модели.
В частности, **Gemma 3n E4B изначально рассчитана на 32K токенов**;
запуск с 64K — экспериментальное расширение контекста, а не гарантия
качественной обработки всех 65536 токенов.

Классификатор инструментов получает сокращённые описания и только необходимые
имена параметров, а не полные JSON Schema. Это устраняет ситуацию, когда
запрос с одной фразой разрастался до 7200 токенов ещё до генерации.

Windows-симулятор поддерживает **продолжение разговора без повторного слова
«Мартин»**. После окончания озвучивания он автоматически слушает следующую
фразу. По умолчанию окно ожидания — **15 секунд** без речи (настраивается в
параметрах симулятора от 5 до 60 секунд). Каждая следующая реплика продолжает
тот же краткий диалог. Когда окно истекает, симулятор посылает
`conversation_reset`, сервер очищает контекст этого WebSocket; для
следующего разговора снова нужно слово активации или кнопка ручной записи.
Долговременная память профиля не удаляется, но не добавляется автоматически
к следующей новой беседе; её можно запросить явно.

Внимание: музыка на громкости может попадать в микрофон; для корректного
свободного диалога желательно использовать Windows Communications AEC и
шумоподавление либо аппаратный эхокомпенсатор в колонке.

## Русские голоса Piper

В каталоге TTS доступны четыре базовых русских голоса Piper, а также дополнительные
**проверенные по наличию файлов ONNX** модели из [rraaww/ru_piper](https://huggingface.co/rraaww/ru_piper)
(Kat580, Pvo240, Sushkov v4, Terra, Mari, Nara) и
[Puriso](https://huggingface.co/dhammagift/piper-ru-puriso).
Последний имеет ограничения **только на некоммерческое использование**
(CC BY-NC-SA 4.0 и OpenRAIL-M). Другие сторонние голоса также требуют
проверки условий лицензирования перед распространением.

**AlwaysReddyRU** — проект голосового ассистента с поддержкой Piper, а не ONNX-голос.
Выбор `high` для русских голосов rhasspy не предлагается: официально опубликованы
только модели `medium`. Качество русской речи в первую очередь зависит от самого
набора данных голоса, а не от слова `high` в его имени.

Для собственной совместимой модели Piper (в том числе модели с пометкой high)
поместите файлы **`models/piper/custom.onnx`** и
**`models/piper/custom.onnx.json`** в корневую папку сервера, затем выберите
**«Piper · Своя ONNX-модель»** в настройках TTS и нажмите «Установить и переключить».
Сервер использует локальные файлы, не скачивает фиктивную модель.
Частота дискретизации и настройки голосовой модели считываются из её JSON.
Параметры скорости и вариативности Piper доступны в панели.

## Музыка

**Яндекс Музыка:** пользователь подключает свой аккаунт через авторизацию по коду устройства либо токен. Доступны поиск композиций, личные плейлисты, треки «Мне нравится», очередь из результатов поиска, рекомендации похожих треков и автоматический переход к следующей композиции после фактического завершения предыдущей. Команды `pause`, `resume`, `next`, `previous`, `stop`, `status` отправляются по WebSocket только соответствующему устройству; очередь отдельных колонок независима.

Команды проходят **один этап классификации намерения**: локальная LLM выбирает нужный
разрешённый инструмент и его параметры либо отсутствие действия. Затем сервер
выполняет его, при необходимости использует результат чтения Home Assistant
для следующего шага и завершает действие. **Повторного** `tool_choice: auto`
во время генерации ответа больше нет — поэтому модель не может отдельно
сообщить «не знаю, какой сервис» и затем выполнить другое действие.

**Музыка и радио считаются запущенными только после получения `media_started`
от подключённого устройства с соответствующим `playbackId`.** Если поток
не открылся, проигрыватель сообщил ошибку или не подтвердил запуск за
15 секунд, сервер выдаёт конкретный отказ, а не «воспроизводится».
Home Assistant подтверждает изменение устройства повторным чтением состояния.
Ответы для выполненных действий формируются из этих фактов; разговорная LLM
используется только когда действие не требуется.

Например, «Мартин, включи группу Кино» приводит к `music_play_query` с
`query="Кино"`, `kind="artist"`. Музыкальный сервис по умолчанию —
подключённая Яндекс Музыка. Команда «Включи свет в коридоре» относится к
Home Assistant, а «включи радио Рекорд» — к Radio Browser: маршрутизация
по смыслу, без регулярных выражений по формулировкам команд.

В браузере автоматическое воспроизведение звука может блокироваться
политикой браузера. В таком случае в чате появится кнопка
«Разрешить воспроизведение музыки». В Windows-симуляторе, если открытие
удалённого потока через Media Foundation не удалось, используется резервное
скачивание во временный файл (не более 40 МБ). Ошибка передаётся серверу.

При активации «Мартин» клиент уменьшает громкость играющей музыки до 18% и восстанавливает после завершения обработки запроса. Это **приглушение**, а не пауза: музыка продолжает идти без изменения позиции. В симуляторе приглушение можно отключить.

Браузерная вкладка «Музыка и радио» содержит отдельный локальный плеер со своей очередью и кнопками управления. Она не заменяет и не синхронизирует воспроизведение на подключённой колонке. Прямые аудиоссылки получаются непосредственно перед началом трека и не хранятся как постоянные URL.

Интеграция использует **неофициальный API Яндекс Музыки**, поэтому доступность каталога, OAuth, подписки, форматы и ссылки могут измениться. DRM-потоки намеренно не обходятся. Если трек недоступен, сервер пробует следующие композиции и сообщает об ошибке. Для реальной проверки требуется авторизованный аккаунт Яндекса и клиентский аудиовыход.

**Интернет-радио:** поиск станций через Radio Browser и передача команды воспроизведения клиенту.

VK Музыка, Spotify, Apple Music, YouTube Music и локальная медиатека пока не подключены. Их пункты в интерфейсе служат обозначением будущих интеграций.

## Клиенты и доступ

Сервер принимает клиентов по **WebSocket** на **/ws**, используя ключ устройства, заданный в панели. Клиент может передать речь в PCM16 mono 16 кГц или текстовый запрос. В ответ он получает распознанный текст, поток ответа LLM, звуковые фреймы и при необходимости команду воспроизведения музыки.

Для тестов без физической колонки используйте [OpenAssistant Simulator](../openassistant-simulator/README.md) на Windows.

В панели можно посмотреть подключённые устройства, состояние LLM/STT/TTS, загрузку GPU, список весов, журналы и историю запросов. Токены интеграций сохраняются в локальных файлах настроек и не выводятся в браузер. Не выставляйте административный интерфейс и WebSocket в интернет без собственной защищённой схемы доступа.

## Пользовательские инструменты LLM

Все встроенные навыки теперь на странице **Сервисы и навыки** с вкладками «Музыка», «Радио», «Умный дом» и «Мои навыки». Доступ Яндекс Музыки модели включается рядом с авторизацией, а разрешения отдельных функций — внутри раскрываемых настроек сервиса. Функции управления Home Assistant требуют отдельного разрешения.

Пользовательский навык создаётся в **трёхшаговом мастере**: название и назначение, схема аргументов (готовый шаблон либо JSON Schema), проверка и сохранение. Определения сохраняются в `custom-tools.local.json` (игнорируется Git), а включённые функции предлагаются модели. Но пока не зарегистрирован соответствующий исполняемый обработчик, это **только описание**: модель получит ошибку «Обработчик ещё не подключён». Мастер явно предупреждает об этом, а не изображает успешное выполнение.

## Поиск устройств в локальной сети

Windows-симулятор имеет кнопку **«Найти и подключиться»**: он рассылает UDP-запросы в локальную подсеть на порт **5056**, получает от сервера HTTP/WebSocket-порт и подключается без ввода IP. В панели **«Устройства» → «Найти устройства»** сервер отправляет запросы на UDP-порт **5057** и перечисляет найденные симуляторы, даже если они ещё не подключились. Обнаружение не передаёт ключи или пароли и не выполняет команды. Ответы принимаются только с адресов приватных IPv4-подсетей.

Поиск работает только между устройствами в одной подсети, если разрешён UDP broadcast. Если нет результата, разрешите входящий UDP 5056 на Ubuntu и UDP 5057 для Windows-симулятора в брандмауэре. Между разными VLAN / Wi-Fi-сетями широковещательные пакеты могут блокироваться. ESP32-P4 будет обнаруживаться сервером после реализации ответчика в её прошивке.

Для более ровной интонации обычный ответ LLM синтезируется целиком одной задачей Qwen3-TTS. Это увеличивает задержку до первого аудио; длинные ответы (>1100 символов) по-прежнему разбиваются по границам предложений.
