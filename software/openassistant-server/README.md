# OpenAssistant Server

Локальный сервер голосового ассистента «Мартин» на .NET 10 для Linux. Принимает речь с устройств по WebSocket, распознаёт её, обращается к LLM, запускает разрешённые инструменты и озвучивает ответ.

## Первый запуск

На Linux нужен .NET SDK 10. Скачайте проект и запустите:

```bash
cd software/openassistant-server
dotnet build -c Release -m:24
dotnet run -c Release --no-build
```

В консоли отображаются только ASCII-логотип и адрес панели. События и ошибки доступны по `/logs.html`.

Откройте `http://127.0.0.1:5055/`. Мастер проведёт через четыре этапа:

1. **Интеллект.** Выберите готовую модель для 8 ГБ VRAM. Сервер скачает конкретный GGUF-файл, найдёт или попробует собрать llama.cpp, запустит модель с автоматическим назначением GPU, дождётся готовности и проверит ответ с замером задержки.
2. **Слух.** Установка GigaAM v3, запуск локального STT-адаптера, запись тестовой фразы через микрофон браузера и замер распознавания.
3. **Голос.** Установка Qwen3-TTS 0.6B CustomVoice, выбор голоса, генерация и скачивание WAV, измерение времени синтеза.
4. **Колонка.** Получение адреса WebSocket, генерация ключа, подключение Windows Simulator или будущей колонки ESP32-P4.

В мастере нет ручного выбора исполняемых файлов, аргументов запуска или путей к весам. При наличии нескольких GPU автоматически выбирается карта с наибольшим объёмом свободной VRAM. Веса языковых моделей представлены конкретными Q8_0-файлами. Видеопамять также нужна для runtime и KV-cache; указанный размер загрузки не равен необходимому объёму VRAM.

**Важное ограничение:** установка движков и Python-зависимостей выполняется на самом Linux-сервере. Для автоматической установки отсутствующих системных пакетов через APT требуются права root; Python-пакеты устанавливаются в системную среду, без venv или Docker. Для CUDA-сборки llama.cpp необходим CUDA Toolkit с `nvcc`; одного драйвера недостаточно. Совместимость PyTorch, CUDA и конкретных GPU проверяется при запуске. Если TTS или STT не работает на выбранной GPU, мастер пробует CPU. При несовместимости окружения статус будет «Ошибка», с причиной и журналом, а не ложное «Готово».

## Разделы интерфейса

- `/` — мастер первоначальной настройки.
- `/control.html` — управление моделями, интеграциями, генерацией и устройствами.
- `/control.html#advanced` — расширенные настройки.
- `/logs.html` — журнал событий Linux-сервера, перенесённый из консоли.
- `/chat.html` — веб-клиент разговора.
- `/models.html` — расширенные параметры GPU и запуска.
- `/connections.html` — Яндекс Музыка и Home Assistant.
- `/media.html` — музыка и интернет-радио.
- `/events.html` — журнал диалогов.

Административные API доступны только через loopback. Для открытия панели с другого компьютера используйте SSH-туннель: `ssh -L 5055:127.0.0.1:5055 user@SERVER_IP`. Для микрофона браузера нужен HTTPS или localhost.

## Как работают модели

LLM общается с llama.cpp по OpenAI-совместимому HTTP API. Для STT используется `POST /v1/audio/transcriptions`, для TTS — `POST /synthesize`, который возвращает WAV PCM16 mono. Сервер передаёт аудио колонке по WebSocket отдельными PCM16-сообщениями. Музыкальные потоки колонка получает напрямую по URL.

Набор агентных инструментов настраивается в панели. Яндекс Музыка, радио и Home Assistant доступны через function calling. Изменяющие состояние устройства инструменты Home Assistant изначально отключены.

Процессы LLM, STT и TTS запускаются под управлением сервера. После его перезапуска сохранённые профили автоматически поднимаются. Разрешения и сохранённые параметры находятся в локальных JSON-файлах, исключённых из Git.

## Ограничения

Полностью безусловная совместимость любой NVIDIA GPU и любой версии Python/Torch не гарантируется. На старых картах современные CUDA-библиотеки могут не поддерживать нужную compute capability. Мастер отображает ошибки установки и запуска, а системный журнал помогает выяснить причину. Поддержка вызовов инструментов зависит от выбранной LLM и её chat template. Полная сборка и интеграционный тест на реальном сервере должны проводиться после обновления.
