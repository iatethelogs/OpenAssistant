# OpenAssistant Server

Сервер голосового ассистента на C# / .NET 10. Приложение не привязано к конкретной колонке: Мартин будет одним из клиентов OpenAssistant.

## Что работает в этой версии

- WebSocket-соединение с клиентом и приём PCM16 mono 16 кГц
- распознавание законченной записи через whisper.cpp
- потоковый ответ локальной LLM через OpenAI-совместимый API
- последовательный синтез предложений через Piper и отправка PCM16 mono на клиент
- настройка голоса заменой модели Piper
- вызов инструментов Home Assistant и каталог интернет-радиостанций через JSON API
- прерывание ответа, отдельный контекст каждого подключения

Это начальный серверный прототип. Потоковый STT, постоянный музыкальный декодер, автоматические вызовы инструментов самой LLM, память SQLite и полноценные интеграции с музыкальными каталогами ещё не реализованы. Для управления API сейчас нужны явные вызовы инструмента, а не произнесённые команды.

## Подготовка

Требуются .NET SDK 10, работающий llama-server, whisper.cpp (whisper-cli) и Piper. Пути к исполняемым файлам и моделям задаются в appsettings.json или переменных окружения OpenAssistant__*. Нельзя хранить токен Home Assistant в репозитории.

```bash
cd software/openassistant-server
dotnet run
```

## Протокол /ws

Одно WebSocket-соединение = один независимый диалог. Клиент отправляет бинарные фреймы с PCM16 LE mono 16 кГц, затем текстовое сообщение `{"type":"end"}`. Можно отправить `{"type":"text","text":"привет"}` без микрофона либо `{"type":"cancel"}`.

Сервер возвращает JSON события `transcript`, `text`, `audio_start`, `audio_end`, `done`, `error`, а между `audio_start` и `audio_end` отправляет бинарные PCM16 LE mono фреймы с частотой `OutputSampleRate`. Для инструментов служит запрос `{"type":"tool","name":"radio","args":{"action":"list"}}` и аналогично `home_assistant`.

В локальной сети настройте Kestrel на нужный IP и защитите управляющий API авторизацией, прежде чем открывать порт другим устройствам.
