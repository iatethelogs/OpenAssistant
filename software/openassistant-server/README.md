# OpenAssistant Server

Сервер OpenAssistant запускает языковую модель, распознавание и синтез речи, обрабатывает запросы от колонок и других клиентов, хранит историю разговоров и подключается к внешним сервисам. Управление выполняется через браузер.

## Установка и первый запуск

Нужен Linux с **.NET 10 SDK**. Для речевых моделей используется системный Python; совместимость ускорения на GPU зависит от драйвера, CUDA и выбранной модели. Для первоначальной загрузки компонентов понадобится интернет.

Из корня репозитория:

~~~bash
cd software/openassistant-server
dotnet run -c Release
~~~

Сервер уже настроен на HTTP-порт **5055** и слушает **0.0.0.0**, поэтому панель и устройство используют один LAN-адрес, например:

- Панель: `http://192.168.1.50:5055/`
- Мастер: `http://192.168.1.50:5055/setup.html`
- Колонка/симулятор: `ws://192.168.1.50:5055/ws`

SSH-туннель для открытия панели в локальной сети не нужен.

**Защита панели:** административные страницы и `/api/` при доступе с другого компьютера в LAN требуют HTTP Basic Auth: логин `admin`. Пароль задаётся **один раз** при запуске через переменную `OPENASSISTANT_PANEL_PASSWORD` и сохраняется в защищённом файле вне репозитория. При последующих запусках повторно вводить пароль не нужно. Пример первого запуска:

~~~bash
cd /root/OpenAssistant
git pull --ff-only origin develop
cd software/openassistant-server
read -rsp "Новый пароль панели: " OPENASSISTANT_PANEL_PASSWORD; echo
export OPENASSISTANT_PANEL_PASSWORD
dotnet run -c Release
~~~

Секреты (пароль панели и ключ устройства) хранятся в `~/.local/state/openassistant/credentials.json` для Linux-пользователя, запускающего сервер (если `XDG_STATE_HOME` не переопределён), с правами `0600` и каталогом `0700`. Они не попадают в Git и не теряются после `git pull` или пересборки. При первом обновлении существующий ключ устройства из `settings.local.json` переносится автоматически. Если файла ключей нет, сервер создаёт ключ только один раз. Повторное использование изменённой переменной `OPENASSISTANT_PANEL_PASSWORD` обновляет сохранённый пароль.

В панели **Устройства** можно посмотреть и скопировать текущий ключ после перезапуска без генерации нового. Кнопка **Перевыпустить ключ** выполняет явную ротацию, после которой колонкам понадобится новый ключ.

На самом Linux-сервере `http://127.0.0.1:5055/` доступен без пароля для начальной настройки. Если пароль ещё ни разу не задавался, удалённая панель заблокирована.

Устройства проходят отдельную проверку по `X-OpenAssistant-Token` (ключ устройства, задаваемый в панели), в том числе внутри LAN. Подключения разрешены с loopback и RFC1918 сетей (10/8, 172.16/12, 192.168/16), но не из интернета. `/health` доступен в LAN без авторизации для проверки связи.

**Важно:** Basic Auth и WebSocket через `http://`/`ws://` не шифруются. Используйте только доверенную LAN, не пробрасывайте порт 5055 в интернет. Для доступа через недоверенные сети настройте TLS/HTTPS (`https://`, `wss://`) и соответствующий защищённый прокси.

Мастер последовательно предложит выбрать языковую модель, настроить распознавание и синтез речи, проверить голос и при необходимости подключить Яндекс Музыку. Модели запускаются через мастер или раздел «Модели»; автоматический старт всех движков после перезапуска сервера пока не предусмотрен.

## Настройка ассистента

В разделе «Настройки» задаются системная инструкция, параметры генерации LLM, язык и голос. Кнопка **«Профиль ассистента»** подставляет рекомендуемые начальные параметры; их можно изменить и сохранить.

Языковые модели работают через llama.cpp и OpenAI-совместимый API. Можно выбрать GGUF из каталога или указать собственную модель. Профили запуска LLM, STT и TTS настраиваются независимо.

Для русского распознавания в мастере используется **GigaAM**, для озвучивания — **Qwen3-TTS**. Доступны готовые голоса CustomVoice и VoiceDesign, создающий голос по описанию. Параметры семплирования, фиксированный seed и строгий режим помогают уменьшить разброс произношения, но VoiceDesign не гарантирует одинакового тембра для любых двух генераций.

Раздел «Диагностика» позволяет записать тестовую фразу с микрофона, проверить распознавание и прослушать синтезированный ответ.

## История и профили собеседников

Разговоры сохраняются на сервере и доступны после нового подключения. В разделе «Диалог» можно выбрать имя профиля, проверить количество сохранённых обменов и удалить историю.

При ответе используются недавние реплики и фрагменты прежних разговоров, найденные по содержанию запроса. Это не автоматическое распознавание личности и не гарантия безошибочного восстановления любого старого факта. Если несколько человек используют общий профиль, их история будет общей.

Клиент может выбрать профиль отдельным WebSocket-сообщением:

~~~json
{"type":"profile","name":"Гость"}
~~~

Если профиль не выбран, используется **«Общий»**.

## Home Assistant

В разделе **«Интеграции»** укажите адрес Home Assistant и долгоживущий токен. После подключения можно обновить список устройств и увидеть их текущие состояния.

Ассистент получает данные из Home Assistant, а не из сохранённого описания дома. Для распознанных запросов о текущем состоянии предусмотрен отдельный серверный обработчик: он запрашивает данные напрямую и формирует ответ по ним. Когда устройство не найдено, ответ неоднозначен или Home Assistant недоступен, сервер не должен подставлять предположение о состоянии.

Управление устройствами **по умолчанию отключено**. Чтобы разрешить действия, включите соответствующий инструмент в разделе интеграций. Сейчас предусмотрены команды для освещения, выключателей, вентиляторов, штор и медиаплееров. Перед отправкой команды проверяется устройство, а после выполняется повторное чтение состояния. Если ожидаемый результат не подтверждён, ассистент сообщает об этом, не объявляя действие завершённым.

Поддерживаются не все домены Home Assistant и не все формулировки запросов. Изменение климатических настроек, создание автоматизаций, работа со сценами и произвольные вызовы сервисов пока не реализованы. Для критичных устройств не следует использовать управление без отдельного контроля.

## Музыка

**Яндекс Музыка:** пользователь подключает свой аккаунт через авторизацию или токен. Реализованы поиск композиций и получение ссылки на воспроизведение; звук воспроизводит совместимый клиент. Полнота каталога, доступность треков и форматы зависят от сервиса.

**Интернет-радио:** поиск станций через Radio Browser и передача команды воспроизведения клиенту.

VK Музыка, Spotify, Apple Music, YouTube Music и локальная медиатека пока не подключены. Их пункты в интерфейсе служат обозначением будущих интеграций.

## Клиенты и доступ

Сервер принимает клиентов по **WebSocket** на **/ws**, используя ключ устройства, заданный в панели. Клиент может передать речь в PCM16 mono 16 кГц или текстовый запрос. В ответ он получает распознанный текст, поток ответа LLM, звуковые фреймы и при необходимости команду воспроизведения музыки.

Для тестов без физической колонки используйте [OpenAssistant Simulator](../openassistant-simulator/README.md) на Windows.

В панели можно посмотреть подключённые устройства, состояние LLM/STT/TTS, загрузку GPU, список весов, журналы и историю запросов. Токены интеграций сохраняются в локальных файлах настроек и не выводятся в браузер. Не выставляйте административный интерфейс и WebSocket в интернет без собственной защищённой схемы доступа.
